# Contributing

## Setup

```bash
npm ci
npm run check
npm run demo
```

Node 22.13 or newer (pdfjs-dist requires it). The toolchain and every dependency are pinned exact, and `package-lock.json` is
committed, so `npm ci` is reproducible.

## The gate

```bash
npm run check
```

It runs lint, build, typecheck (`svelte-check` for the demo) and the test suites. A change is not
done until the gate passes with no errors. Never loosen a test or an assertion to get there.

Core tests are `node:test` and run against compiled output. Demo tests spawn the built server on a
port of their own and exercise HTTP, so they need `npm run build` first; `check` does that for you.

## Layout

- `packages/core` is a pure library. It has no file system access and one runtime dependency,
  `pdfjs-dist`. Anything that touches the outside world belongs behind a port.
- `apps/demo` wires adapters into core and serves the UI.
- `fixtures` is generated by `npm run fixtures`; commit the output so a clone needs no regeneration.

## Adding a dependency

Every dependency is pinned exact and needs a one-line justification in the pull request. Prefer the
standard library and the dependencies already present. A new runtime dependency in core needs a
strong argument; adapters are the place for integration weight.

## Changes

- One logical change per commit. Subjects use `feat:`, `fix:`, `chore:`, `docs:`, `test:` or
  `refactor:`.
- Work on a short-lived branch. `main` takes changes through a pull request.
- Update `CHANGELOG.md` in the same commit as the change.
- A new externally-triggered path gets a test: the happy path, one edge case, and the fields that
  matter.
- Refactors ship separately from behaviour changes.

## Clean room

This repository is a clean-room rewrite. Do not add a client name, a client identifier, a metric
from a real engagement, or copied code. Fixtures use the fictional Northgate Interiors distributor
and its customers. If a change needs a new fixture, generate it with `npm run fixtures`.

## Writing

Documentation follows the structure in `README.md`: an overview on the front page, procedures in
`docs/`, one home per procedure. Diagrams are Mermaid unless a screenshot carries the information
better.
